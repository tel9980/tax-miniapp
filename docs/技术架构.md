# 技术架构与数据来源说明

> 这份文档回答「数据从哪来、怎么变成页面上的卡片、哪些地方不可靠」。改代码前先看这里。

## 一、总览

```
国家税务总局政策法规库(8 个栏目)  ┐
广东省税务局(2 个栏目)            ├─→ Worker 抓取/解析/去重/判定 ─→ KV(24h) ─→ /api/* ─→ 网页 + 小程序
总局全文搜索(5 个区域关键词)       │        ↑
内置 seed(区域优惠 13 条)         ┘   每天 09:00 cron
```

- 没有任何数据库、没有用户系统、不收任何数据。
- 所有内容每天自动重新抓一次，抓不到就继续用上一次的（不空屏）。

## 二、数据源（全部是税务系统官网，无第三方）

### 1. 总局政策法规库列表

```
POST https://www.chinatax.gov.cn/getFileListByCodeId
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
Referer: https://fgk.chinatax.gov.cn/zcfgk/
X-Requested-With: XMLHttpRequest

body: codeId=&channelId=<栏目UUID>&page=0&size=50
```

返回 `results.data.results[]`，每条含 `title` / `url` / `publishedTime` / `domainMetaList.resultList`（键值对：`writtentext` 发文字号、`writtendate` 成文日期、`taxpolicy` 税种、`effectlevel` 效力等级、`writtendepartment` 发文单位、`abolishdate` 废止日期）。

**抓取的 8 个栏目**（`worker/index.js` 里 `COLUMNS`）：

| 栏目 | 代码 | channelId |
|---|---|---|
| 财税文件 | c102416 | 2cb303fdee614232b79552d52bb057d6 |
| 税务规范性文件 | c100012 | 470b437b304f434396500a1e2edc7f28 |
| 政策法规文件 | c100006 | 29a88b67e4b149cfa9fac7919dfb08a5 |
| 法律 | c100009 | d34fa7ad03f84f4caed12f5c2beae099 |
| 行政法规 | c100010 | e1cd1569d1ea4a25a11041248925a081 |
| 国务院文件 | c102440 | fa1726b47078490fa0a4522194185e8d |
| 其他文件 | c100013 | 4c1a5be62f6d44d48f386f630dcebbc5 |
| 工作通知 | c102424 | 7778c3a40a344de3a36ca88a2548f5f8 |

> ⚠️ 官方返回的 `url` 域名是 `www.chinatax.gov.cn`，但那个域名下的 `/zcfgk/` 路径是 404。真实的政策库域名是 **`fgk.chinatax.gov.cn`**，代码里统一做了域名替换。

### 2. 广东省税务局（服务端渲染 HTML，不是接口）

| 栏目 | 路径 |
|---|---|
| 政策文件 | `https://guangdong.chinatax.gov.cn/gdsw/zcwj/zcwj.shtml` |
| 最新文件 | `https://guangdong.chinatax.gov.cn/gdsw/zxwj/zxwj.shtml` |

解析方式：正则抓 `<li><h4><a href title>标题</a><span class="time">[日期]</span></h4></li>`，日期要 strip 掉方括号（两个栏目一个有方括号一个没有）。

### 3. 总局全文搜索（用来捞区域政策）

```
GET https://www.chinatax.gov.cn/search5/search/s
  ?searchWord=<关键词>&siteCode=bm29000002&pageSize=20&pageNum=0&orderBy=4&searchSiteName=GSFFK
Referer: https://fgk.chinatax.gov.cn/zcfgk/
X-Requested-With: XMLHttpRequest
```

返回 `searchResultAll.searchTotal[]`，字段 `title`（带 `<span>` 高亮要洗掉）、`url`、`cwrq`、`govDoc.docNum`、`xxgk_taxPolicy`、`xxgk_taxDiscount` 等。

关键词 5 个（`REGIONAL_KEYWORDS`）：横琴、前海、南沙、粤港澳大湾区、河套深港。

**这个接口有反爬**：短时间连续请求会返回 HTML 而不是 JSON。代码里做了 3 次指数退避重试（1.2s 起）+ 关键词之间串行间隔 1 秒。CF 的出口 IP 尤其容易被限。

### 4. 内置 seed（`REGIONAL_SEED`，13 条）

为什么需要硬编码？因为**总局法规库对区域优惠政策收录严重不全**。实测：

- 搜「财税〔2022〕19号」（横琴企业所得税 15%）→ 0 条命中；
- 「财税〔2022〕3号」「〔2022〕29号」（横琴/南沙个税 15%）→ 搜出 10 条无关结果；
- 「财税〔2026〕3号」（前海延续）→ 搜出 10 条无关结果。

也就是这些**真实存在、正在执行**的文件根本没有被索引。所以核心区域政策写死在 `REGIONAL_SEED`，附上已核实的文号、日期、政策要点，搜索接口只用来自动补充新出的文件。seed 和动态抓取的同一条会按发文字号去重，seed 优先。

## 三、每条政策是怎么「算」出来的

### 优惠判定

官方接口不返回「是否优惠」字段，用关键词判定：

- **正面词**：免征、免税、减征、减半、减按、退税、即征即退、留抵退税、加计扣除、抵免、减免、优惠、零税率等；
- **否定词**（`NEG_KEYWORDS`，命中就不算优惠）：废止、取消、失效、作废、撤销、不再执行、不再实施、停止执行、终止执行。

判定结果打 `isPreference` / `prefType`（免税/减税/退税/加计扣除/抵免）标签。**这是机器判定，不是官方结论**，页面上已注明以原文为准。

### 有效期与状态

`parseExpiry(text, date)` 按顺序试 4 类写法：

1. `至YYYY年MM月DD日` / `至YYYY年底`
2. `延续实施…至YYYY年`
3. 范围式 `(\d{4})…[—–~至到]…(\d{4})年`，取结束年
4. `有效期X年`

再叠加对照：`十五五`→2030-12-31、`十四五`→2025-12-31、`EFFECTIVE_UNTIL` 表（小微、小规模、六税两费、个体户、研发加计扣除等高频政策人工核对过的到期日）。

`judgeStatus()` 输出：`已到期` / `即将到期`（半年内）/ `生效中` / `未标注`。

> 注意：官方 `abolishdate` 字段对「未废止」返回的是**字符串 `"null"`**，不是 null，要排除掉，否则全站政策都会被判成已废止。

### NEW 标记

KV 里存一份 `seen = { 政策id: 首次见到的日期 }` 快照，每次抓取对比：

- 不在快照里 → 记为今天首次见到，`isNew = true`；
- 首次运行（快照不存在）→ 全部记为已见，**不标 NEW**（否则上线第一天满屏 NEW）；
- 超过 7 天自动不再 NEW。

### 一句话看懂（plain）

两档兜底：

1. **真摘要**：抓详情页正文，取「现就/现将/通知如下」之后的第一段，截 160 字。**只对前 10 条优惠类政策做**——CF 免费计划 CPU 约 10ms，抓多了会被中断（实测抓 60 条时线上覆盖率只有 42%，本地 Node 没这个限制所以看不出来）。
2. **模板摘要**：零子请求拼一句话（优惠类型 + 税种 + 区域 + 执行至），其余条目用这个。

### 去重

按发文字号 `docNo` 去重（`doc:` + 去掉空白的文号），没有文号才用 `id`。重复时 **seed 覆盖动态抓取**，因为 seed 的信息经过人工核对。

> 踩过的坑：早期按 id 去重，导致横琴的政策在列表里出现 8 条重复。

## 四、API 契约

| 接口 | 内容 | 是否抓网 |
|---|---|---|
| `GET /api/policies` | 政策库全量（383 条左右） | 缓存命中不抓；过期先给旧数据后台刷 |
| `GET /api/refresh` | 强制重抓并写 KV，返回统计 | 是，10~30s |
| `GET /api/vat-continuity` | 增值税新法衔接表（58 条静态） | 否 |
| `GET /api/cit-continuity` | 企业所得税到期地图（24 条静态） | 否 |
| `GET /api/iit-continuity` | 个人所得税到期地图（25 条静态） | 否 |
| `GET /api/detail?id=` | 单篇政策正文（纯文本段落，最多 6000 字） | 是，抓一次后 KV 缓存 `d:<id>` |

`/api/policies` 条目字段：`id` `title` `docNo` `date` `url` `taxTypes` `effectLevel` `department` `isPreference` `prefType` `column` `region`(全国/广东) `area`(横琴/前海/南沙/大湾区/河套) `expiry` `status` `plain` `isNew`。

`url` **可能为 null**（法规库未收录），前端这时渲染成不可点卡片 + 提示，绝不会退回官网首页。

三张对照表统一结构：`{ law, groups[], items[], total, updatedAt }`，`items` 字段 `g`(分组) `status` `until` `basis` `title` `plain` `docNo` `url`。

## 五、前端

### 网页版（`web/`）

- 4 个 tab：政策库 / 增值税衔接表 / 所得税到期地图 / 个税到期地图；
- 政策库筛选：地区(全国+广东) / 区域 / 状态 / 只看优惠 / 税种 / NEW / 我的收藏；
- 分页 40 条一页（「加载更多」），搜索走标题+文号+摘要；
- 收藏、筛选条件存 `localStorage`（`tax-favs` / `tax-filter`）；
- 三张表共用一个渲染器 `makeContinuity()`，加新表只需加一段配置。

### 微信小程序（`miniprogram/`）

- 2 个 tabBar 页 + 1 个详情页：政策库、衔接表（衔接表内再切 3 张表，**一套通用渲染**）、政策详情；
- 点卡片 → `pages/detail` 读 `/api/detail?id=`，正文由后端抓取清洗后按段落渲染（首屏 2~3 秒，之后走 KV 缓存约 250ms）；
- 长按卡片 = 复制原文链接（想自己去官网看的场景）；
- 无链接条目会弹窗提示按文号自查 / 拨 12366。

## 六、已知限制（都写在这，不要当成 bug 再查一遍）

1. **小程序上线卡在域名备案**。`wx.request` 只允许备案域名，`jy.1211.cc.cd` 在 Cloudflare 上没备案 → 开发者工具里勾「不校验合法域名」能跑，真机/发布会被拦。三条出路：换备案域名指向同一 Worker / 静态打包随版本发 / 微信云开发（要钱）。
   - 同理，小程序**不能直接打开外部网页**：`web-view` 组件要求把域名配进「业务域名」，而业务域名同样必须已备案。所以正文改为后端抓取 + 前端自己渲染（`worker/detail.js` → `/api/detail?id=`）。
2. **横琴、南沙的区域优惠「待核实」**。原文件执行到 2025-12-31，总局+财政部+省局三个渠道都没检索到延续文件（前海已被深圳税务局 12366 问答确认延续到 2027-12-31）。页面上明确标「⚠️ 待核实 · 需人工确认」，不猜。
3. **优惠判定是关键词匹配**，可能误判（标题里出现「废止」二字但实际是别的意思），以原文为准。
4. **CF 免费计划 CPU 限制**导致只能给 10 条政策抓真正文摘要，其余是模板摘要。
5. 政策库抓的是各栏目「最新 N 条」，不是全库回溯（法律法规库总量上万条）。
